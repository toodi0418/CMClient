# CMClient 2.0.0-rc.1

This is a release-candidate evidence package, not a production release. The
artifact identity is SemVer `2.0.0-rc.1`; its channel is `beta` under the
repository's prerelease policy. The immutable source identity is the checkout
SHA recorded in `release-index.json` and in the matching GitHub Actions run.
Do not substitute a branch name or a later commit.

## Delivery set

The canonical matrix contains 16 updater-safe portable archives:

- Desktop, Headless, CLI, and (Windows) Service for
  `darwin-aarch64`, `darwin-x86_64`, `linux-aarch64`, `linux-x86_64`, and
  `windows-x86_64` where the component is supported.
- Native Desktop DMG, DEB, AppImage, MSI, and NSIS packages (8 files), each
  embedding the complete portable composition at `cmclient-runtime/`.
- Linux x64 and ARM64 constrained OCI archives with source/digest metadata.
- A versioned Docker Compose descriptor for the fixed Gateway/Web/Ingress
  topology.
- Checksums, exact release index, staged-composition SBOM, and one SBOM per OCI
  image.

Native packages and OCI archives are checksum/provenance subjects but are not
Agent updater bundles. In ordinary `dev` and pull-request runs, native
packages are intentionally unsigned. A protected production tag may replace
their bytes with Apple-signed/notarized/stapled Darwin packages,
timestamped-Authenticode Windows packages, and GPG-signed AppImages verified
with the checksum-pinned AppImageUpdate validator; Linux DEB remains
checksum/provenance-bound. The finalizer records per-target
platform-signing receipts and regenerates the SBOM, release index, and
`SHA256SUMS` before attestation. The Windows MSI uses the internal numeric
prerelease `2.0.0-1` required by WiX; all external filenames, manifests,
checksums, and the release index remain `2.0.0-rc.1`.

## Verification

Before extraction or import, verify the complete downloaded release directory
with `sha256sum -c SHA256SUMS`. To verify one downloaded subject, extract its
exact `sha256 *filename` row, require exactly one match, and check that row as
shown in [Getting Started](../user/getting-started.md); never use
`--ignore-missing`. The release workflow must pass the canonical artifact-plan,
resource/load, security/dependency/secret, native packaging, Docker no-build
import, final Windows SCM, checksum, SBOM, and extracted runtime smokes. Record
the run URLs, artifact ID/digest/expiry, `release-index.json`, platform-signing
receipts when applicable, and checksum output in the field-validation evidence
before promotion. This document does not claim those external values until the
current source commit has passed. A production artifact is not eligible for
Cosign or GitHub provenance until `verify --require-platform-signing` has
accepted the re-finalized bytes.

The field plan is fixed at five targets, twenty modes, twenty-six required
cases, and 129 case-target-mode executions. Use
`docs/testing/rc-field-validation.md` and its JSON plan as the checklist; do
not silently reduce it for a platform that is unavailable.

## Main changes

- Rust Agent owns lifecycle, local IPC, Management Web, updates, backup,
  rollback, and service supervision.
- Fastify Gateway owns Meshtastic normalization, SQLite/WAL persistence,
  Jobs/SSE, Position/APRS ordering, CallMesh, and protocol-aware TCP Proxy.
- Vue Web, Tauri Desktop, and Rust CLI consume shared contracts and stable
  error codes rather than reaching into runtime internals.
- Service mode writes bounded, retained, redacted JSONL for Agent, Gateway, and
  the Windows SCM host; platform managers expose only bounded application logs
  or stable-code fallback output.
- Position/APRS processing is per mesh node/callsign, byte-identical across
  iGates, and fail-closed when freshness, trusted event time, or 32-bit GPS
  precision is not proven.
- Supply-chain assembly is source-bound, checksum-covered, and SBOM-covered;
  ordinary `dev` runs are explicitly unsigned, while protected production
  signing is followed by receipt-bound re-finalization before attestation.

## Removed and disabled behavior

TENMAN and TENMAP sharing, their environment/configuration/database/UI paths,
and the old `@cm` Bot are removed without a compatibility layer. Remote Message
Dispatch is a later independent capability and is reported unavailable with
`REMOTE_DISPATCH_NOT_ENABLED`. Docker cannot self-update or access host
serial/service controls. Native Desktop packages do not auto-register a
privileged Agent.

## Upgrade and known limits

Keep configuration, data, cache, logs, and the update journal outside the
versioned release directory. Agent updates are the only supported in-place
upgrade path once a signed manifest exists; the RC has no public browser update
trigger. Docker is operator-upgraded from its OCI archive after an OCI-to-Docker
archive conversion and must be launched with the versioned compose descriptor
and explicit `CMCLIENT_IMAGE`. Hardware transport validation is represented by
simulators, fixtures, replay, and CI smoke; a physical Meshtastic radio is still
required for field hardware sign-off.

The security audit carries a narrowly scoped, time-bounded RustSec exception
documented in `docs/security/release-audit.md`. It is not a claim that all
production signing, notarization, or code-signing credentials are present.

## Promotion gate

P12-T05 still requires explicit human approval for the production environment,
exact tag, platform signing/notarization credentials, attestation, and final
release publication. The required order is platform signing and receipt
creation, re-finalization with regenerated SBOM/index/checksums,
`--require-platform-signing` verification, keyless checksum/provenance
attestation, and only then update-manifest signing. Until that approval and its
external evidence are recorded, this RC must not be called `2.0.0`, production
signed, or published from `main`.
Approval is followed by a reviewed release-only `2.0.0` version commit; the
production evidence must independently bind that commit, `v2.0.0`, its CI and
tagged Release Build Matrix runs, and the attested artifact digest without
overwriting this RC's identity.
